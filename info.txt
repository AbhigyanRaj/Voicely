3. THE REAL-TIME AI PIPELINE (STEP-BY-STEP)
--------------------------------------------------------------------------------
The project's primary technical achievement is the "Zero-Wait" pipeline:

Step 1: Audio Ingest (Twilio -> Backend)
   - Twilio establishes a bi-directional WebSocket connection.
   - Raw 'mulaw' 8kHz audio packets are streamed to the backend.

Step 2: Real-time STT (Backend -> Deepgram)
   - The backend forwards audio bytes to Deepgram Live.
   - Deepgram returns "Interim" (partial) and "Final" transcripts.

Step 3: Intelligence (Deepgram -> Gemini)
   - Transcripts are fed into the 'StreamingCallHandler'.
   - It maintains short-term memory (Chat History) and Persona (System Prompt).
   - Gemini 1.5 Flash starts streaming tokens immediately.

Step 4: Sentence Boundary Buffering (Gemini -> TTS)
   - The system does NOT wait for the full AI response.
   - It buffers tokens until it detects a sentence boundary (., !, ?, or ,).
   - Once a sentence is complete, it is sent to TTS while the next sentence 
     is still being generated.

Step 5: Audio Output (TTS -> Twilio)
   - TTS returns 'mulaw' audio base64 packets.
   - These are sent back through the WebSocket to Twilio for immediate playback.

4. KEY TECHNICAL FEATURES
--------------------------------------------------------------------------------
A. BARGE-IN DETECTION (INTERRUPTION HANDLING)
   - The system constantly monitors for user speech.
   - If a user speaks while the AI is talking, a 'clear' signal is sent to 
     Twilio, killing the current audio queue.
   - The AI stops thinking and waits for the new user input.

B. REGIONAL LANGUAGE MASTERY
   - Specifically optimized for the Indian market.
   - Uses Deepgram Nova-3 for superior accuracy in Hindi, Marathi, Telugu, etc.
   - Leverages Sarvam AI TTS for natural-sounding regional accents.

C. HUMAN-IN-THE-LOOP (INTERVENTION)
   - A live dashboard allows admins to monitor active calls.
   - "Executive Intervention": Admins can type a response, which the AI 
     immediately speaks into the call, effectively taking over the conversation.

D. DEEP BEHAVIORAL ANALYTICS
   - Post-call, Gemini performs a "Deep Analysis" of the transcript.
   - Extracts: Sentiment, Objections, Intent Tiers (High/Medium/Low), and 
     structured JSON answers to specific business questions.

6. DATA ARCHITECTURE
--------------------------------------------------------------------------------
- CALL: Linked to Module, Workspace, and User. Stores duration, status, 
  transcription, and a complex 'evaluation' object.
- MODULE: Defines the AI's "Job." Contains persona, system prompt, and a 
  set of questions to be asked sequentially.
- LEAD: Represents a long-term customer. Stores a 'Timeline' of all 
  interactions/calls with that specific phone number.

7. LATENCY OPTIMIZATION SECRETS
--------------------------------------------------------------------------------
1. Direct Mulaw: Requests audio in mulaw format from Google TTS to avoid 
   FFmpeg transcoding delay.
2. Global V1 Endpoint: Forces stable v1/v1beta API endpoints for Gemini 
   to avoid experimental latency spikes.
3. Cold-Start Mitigation: Pre-initializes STT/TTS connections before the 
   user starts speaking.
